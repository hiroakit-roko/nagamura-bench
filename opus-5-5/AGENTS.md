あなたは **Claude Opus 5.5** として、このベンチマークに参加しています。
このフォルダ（`opus-5-5/`）があなた専用の作業領域です。ユーザーから「開始して」等の指示があったら、

途中で確認の質問をする必要はありません。判断が必要な箇所は、自分で最善と思う選択をして `REPORT.md` に理由を残してください。

## 1. 課題

株式会社長村製作所（精密板金加工）の公式サイト **https://nagamura.co.jp/** をリニューアルしてください。

- 目標：**今よりずっとモダンで、かっこよく、リッチな見た目** のコーポレートサイト。
  「このベンチマークで一番すごいサイトを作る」つもりで、デザイン力・表現力・技術力を出し切ってください。
- 既存サイトに掲載されている **情報は漏れなく網羅** すること（見た目は一新、中身は失わない）。

### 評価観点
1. ビジュアルのインパクトと洗練度（ファーストビュー、タイポグラフィ、配色、余白、モーション）
2. リッチな表現（写真の活用・加工、3D / WebGL、インタラクション、スクロール演出 など）
3. 既存コンテンツの網羅性と正確さ（社名・住所・電話番号・設備台数・数値などを改変しない）
4. 情報設計とユーザビリティ（ナビゲーション、採用・問合せ導線、読みやすさ）
5. レスポンシブ対応（スマホ〜ワイドモニタ）、アクセシビリティ、表示速度
6. デプロイされ、実際に動いていること（リンク切れ・画像切れ・JSエラーがないこと）

## 2. 進め方

### Step 1: 既存サイトの徹底調査（惜しみなくやること）
- トップページだけでなく、**すべての下層ページ・サブページ** をクロールして読み込むこと。
  主要ページ（2026年9月時点）:
  `/advantage/`（強み） `/management/`（経営方針） `/company/`（会社概要） `/technology/`（技術情報）
  `/equipment/`（設備概要） `/products/`（製品紹介） `/blog/`（社長ブログ） `/blog_cio/`（ITブログ）
  `/recruit/`（採用情報） `/faq/`（よくある質問） `/contact/`（お問合せ）
  ※ これ以外にもリンクされているページ（下層ページ、事例、アクセス、プライバシーポリシー等）があれば全て対象です。
- WebFetch だけで取れない情報は `curl` で HTML を取得して解析する等、手段を尽くしてください。
- 必要に応じて Web 検索も行い、会社の特徴・実績・ニュースなど、サイト作りに役立つ情報を集めてください
  （ただし、サイトに載せる事実は公式情報に基づくこと。推測で数値や実績を作らないこと）。
- 調査結果は **`docs/content-inventory.md`** に「元ページURL → 掲載情報の一覧」として記録すること。
  最終的にこのインベントリの全項目が新サイトに反映されているかをチェックリストとして使います。

### Step 2: 素材の収集と加工
- 既存サイトにアップロードされている **写真・画像を惜しみなく収集** し（`curl` 等でダウンロード）、
  その中から **最も良いと思うもの** を選んで使ってください。
- 画像は積極的に加工してOK：トリミング、色調補正・グレーディング、ダブルトーン、合成、ぼかし背景、
  WebP/AVIF 変換、レスポンシブ用の複数サイズ生成など（`sips`, ImageMagick, `sharp`, Python/Pillow 等、使える手段は何でも）。
- **3D モデリング / WebGL も歓迎** します（例：Three.js 等で板金部品・曲げ加工・工場・金属質感などを表現）。
  手続き的モデリング、シェーダー、パーティクル、スクロール連動アニメーションなど、リッチさを追求してください。
- 実写真は会社の実物を優先。外部のフリー素材・フォント・ライブラリを使う場合はライセンスを確認し、
  **`CREDITS.md`** に出典とライセンスを記録すること。実在しない製品・設備・人物を「実物」として見せないこと。
- 取得した素材は `assets/` 等このフォルダ内に置くこと（外部サイトの画像への直リンク（ホットリンク）はしない）。

### Step 3: 設計・実装
- ページ構成は既存サイトの全ページ分を用意すること（1ページのLPにまとめて情報を落とすのはNG。
  統合・再構成は可だが、全情報にたどり着けること）。
- ブログ（社長ブログ / ITブログ）は、全記事の移植までは不要。記事一覧（タイトル・日付・元記事へのリンク）
  や最新記事の紹介など、ブログの存在と中身がわかる形で再設計してください。移植する場合は歓迎します。
- お問合せフォーム：サーバーは無いので、フォームUIは作ってよいが送信は `mailto:` か元サイトの問合せページへの誘導にすること。
  電話番号・FAX・所在地などの連絡先情報は必ず正確に掲載。
- 技術スタックは自由（素の HTML/CSS/JS、Vite、Astro、React、Three.js、GSAP など何でも）。
- `prefers-reduced-motion` への配慮、キーボード操作、alt テキスト、日本語タイポグラフィ（行間・字間・改行）にも気を配ること。

### Step 4: 検証
- ローカルでプレビューして全ページを確認すること（例：`python3 -m http.server` / `npx serve` / `npm run preview`）。
- 可能ならブラウザ（Playwright やブラウザ操作ツール等）でスクリーンショットを撮り、**デスクトップとスマホ幅の両方** で
  崩れ・画像切れ・コンソールエラーが無いか確認して修正すること。
- `docs/content-inventory.md` と突き合わせて、情報の抜け漏れが無いか確認すること。

### Step 5: デプロイ
下記「4. デプロイ方法」に従って push し、GitHub Actions の成功と公開URLでの表示を確認すること。

### Step 6: レポート
このフォルダに **`REPORT.md`** を作成：
- デザインコンセプト / 配色・フォント / 技術スタック
- ページ構成（元サイトのページとの対応表）
- 使用した写真・加工内容・3D表現の説明
- 工夫した点、妥協した点、既知の問題
- 公開URL

## 4. デプロイ方法（GitHub Pages）

このリポジトリは `main` ブランチへの push で GitHub Actions が走り、全モデルのサイトをまとめて GitHub Pages に公開します。
あなたのサイトは **`https://<owner>.github.io/<repo>/opus-5-5/`** で公開されます
（`<owner>/<repo>` は `gh repo view --json nameWithOwner -q .nameWithOwner` で確認できます）。

### 公開のされ方
- **ビルドツールを使わない場合**：このフォルダの中身がそのまま `/opus-5-5/` に配置されます。
  `index.html` をこのフォルダ直下に置いてください。
- **ビルドツールを使う場合**：このフォルダ直下に `package.json` を置き、`npm run build` で
  **`dist/`** に静的ファイルを出力するようにしてください。Actions が `npm ci`（lock が無ければ `npm install`）→
  `npm run build` を実行し、`dist/` の中身を `/opus-5-5/` に配置します。`package-lock.json` はコミットしてください。
  Node.js のバージョンは 22 です。

### パスの注意
- サイトはサブディレクトリ（`/<repo>/opus-5-5/`）配下で配信されます。**絶対パス（`/assets/...`）は使わず相対パスを使う** こと。
  Vite なら `base: './'`、Astro なら `base` に `/<repo>/opus-5-5` を設定する等で対応してください。
- GitHub Pages は SPA のフォールバックを持たないため、SPA にする場合はハッシュルーティングにするか、
  各ページ分の HTML を出力（静的生成）してください。マルチページの静的HTMLが最も安全です。

### push 手順
```bash
# このフォルダの変更だけをコミットする
git add -A -- .
git commit -m "[opus-5-5] <変更内容>"
git pull --rebase origin main   # 他モデルも並行で push しているため
git push origin main
```
- push 後、`gh run list --limit 3` / `gh run watch` で Actions の成功を確認し、公開URLにアクセスして
  表示・画像・リンクが正しいことを確認してください（`curl -I` 等でも可）。
- ビルドに失敗した場合は、そのモデルのサイトだけ「ビルド失敗」ページになります。ログ（`gh run view --log-failed`）を見て修正してください。
